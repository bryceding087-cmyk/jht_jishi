# 故事入口与润色分支示例

以下为 v0.2.0 的设计场景，不是已发生的调用、用户授权或生成结果。故事版本和操作名称用于说明状态变化。

## 完整故事

用户输入的故事已能交代主体、事件与想表达的结果，导演判断足以进入制作，返回 `complete / normal`。主控直接分析内容量与台词时长，跳过润色，不要求用户为了继续而先点击“优化故事”。不强制所有作品具备冲突或反转。

## 有关键缺项，由用户决定

用户输入只给出人物和一个笼统结果，没有说明发生了什么，也无法确定表达意图。导演指出具体缺项与影响，返回 `needs_input / waiting`，保存当前故事版本 S1。

对话说明缺少哪些制作所需信息，提供补充故事、补全并润色、沿用原文三个操作。展示操作入口本身不触发改写。

| 用户主动选择 | 状态与后续 |
| --- | --- |
| 用户自行补充关键事件与表达意图 | 保存 S2，由导演重审，再分析 S2 |
| 补全并润色 | 记录授权范围；调用专用工具形成 D1，展示完整稿、差异与保留项检查，工作稿仍为 S1 |
| 沿用原文继续 | 保持 S1，记录已接受的缺项，继续策略改为 user_accepts_gaps；评估仍为 needs_input，不自行补写冲突或领悟 |

沿用原文后在创意中说明具体缺项和用户接受的取舍，不杜撰成已确认的台词或情节。输入完全为空则请求至少给出可识别的故事内容。

## 润色稿采用前后

假设用户只授权“帮我补全后看看”，工具返回 D1。导演或自审核对后仍不能将 D1 用于时长分析、创意、分镜或媒体生成。

| 动作 | working_story_ref | 对下游的影响 |
| --- | --- | --- |
| D1 生成并展示，用户尚未选择 | S1 | 不改变采用稿，不使现有产物失效 |
| 用户采用 D1 | D1 | 重审 D1，只更新受实际内容变化影响的下游产物 |
| 用户要求继续编辑 D1 | S1 | 形成 D2 草稿，采用前仍不影响下游 |
| 用户选择保留原文并接受缺项 | S1 | 继续使用原文和已记录取舍 |

若用户一开始明确要求“补全润色后直接继续”，保真检查通过后可以按该授权采用，并展示实际差异；若用户仅说“风格你来定”，不能据此调用故事补全。

## 有意留白与纯措辞润色

故事可以在人物作出决定时结束，而不展示后续结果。只要足以表达创作意图，导演不能仅因结尾留白就判定缺项。

用户要求“只把叙述写顺，台词一字别改”时使用 `wording_only`，不添加动机、事件或结尾。任何未获准的精确台词变化先修正，再展示草稿；已有视频提示词润色功能不能替代此操作。
