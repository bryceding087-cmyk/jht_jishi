# 修改与恢复

输入为用户变更或失败事件、当前运行、依赖图、任务及授权。先用 `jht_run_load` 核对最新状态。

## 修改影响

| 用户修改 | 需要复核或更新的产物 |
| --- | --- |
| 采用补全或润色后的故事 | 导演重新检查，重新分析内容量与时长，按故事差异使创意和关联下游失效 |
| 润色稿尚未采用或用户保留原文 | 工作稿保持不变，不使既有创意或媒体自动失效 |
| 品牌片尾文字或字幕样式 | 文字轨、时间线、渲染和成片检查 |
| 一句台词 | 台词、配音、字幕；按时长和口型依赖决定是否重做镜头 |
| 人物外貌 | 人物参考和采用它的片段，必要的后期与检查 |
| 镜头顺序或长度 | 镜号映射、时间线、配乐区间、字幕与依赖尾帧的片段 |
| 视频模型或生成规格 | 相关提示词、能力与费用方案、受影响视频任务 |
| 项目名称或画布位置 | 展示信息；不使无关媒体失效 |
| 创意稿只回填真实素材路径 | 更新绑定版本与展示，不重做同一创意内容下已生成的素材 |

保存 `RevisionPlan`，保留旧版本，将受影响依赖标为 `stale`。确认只在内容或费用超出已有范围时失效，不要求用户重新批准全部无关成果。建议主控调用对应制作 Skill，不在本 Skill 无差别重生成。

BGM 已提前生成时，分镜长度或顺序变化先判断可否通过后期适配复用音乐；只有不能满足新方案才重制。更新计划时间线与对应音乐引用，防止旧版分镜的节拍表继续被标为当前版本。

## 任务恢复

按任务类型调用 `jht_video_query`、`jht_images_query`、`jht_audio_query` 或 `jht_render_query` 核对实际状态。存在成功结果时先复用；下载失败交视频缓存流程；渲染失败交后期流程。

提交结果未知时保持 `unknown` 并交运行层核对请求记录，不能直接增大尝试次数重发。明确失败且可重试时，检查剩余预算、输入修复和次数上限，再建议对应生成 Skill 重试。

已有视频查询接口不等于能自动恢复供应商轮询；现有图片任务也可能在服务重启后中断。工具不具备恢复能力时返回真实缺口，保留任务与素材线索。

接续旧定义版本的项目时记录版本差异并核对采用稿和已有确认。能够证明有效的成果继续复用，不因新增导演审查或调整 BGM 阶段而强制整项目重做；缺少新阶段所需信息时只补相关检查与依赖。

## 暂停、恢复与取消

用户明确要求时调用 `jht_run_control`。暂停停止新提交，保留在途任务；恢复先查询和重新核对版本；取消尽可能停止供应商任务，分别记录运行取消与上游取消是否成功。

## 返回与检查

按[统一协议](../../contracts/runtime.md)返回 `RevisionPlan`、真实任务状态、可复用成果和下一步。用户取消后不继续新生成；已发生费用不因本地状态改为取消而抹除。

反复出现相同失败、需要超额费用或无法判断提交结果时停止受影响的操作，向主控返回具体问题与可审阅方案。
