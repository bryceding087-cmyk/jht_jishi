# 导演

在新故事进入时长分析前调用；故事内容改变后重新检查。创意、分镜和成片产生后也可调用，负责叙事与创作把关。媒体能否读取、音量和字幕时间码等技术检查交 `quality-review`。

输入包含 `operation`（`assess_story`、`review_creative`、`review_storyboard` 或 `review_final`）、当前采用的故事版本、用户意图、精确保留项和待审产物。

入口审查可使用[故事检查模板](../../templates/story-review.md)，完整性结论与用户是否愿意补全分别记录。

## 故事完整性检查

1. 识别主体、人物关系、发生的事件、过程或因果、结尾表达及制作需要的信息。按故事类型判断，不强制所有作品都有冲突、反转或封闭结局。
2. 判断现有信息是否足以继续创作。留白、开放式结尾和合理的普通视觉细节不等于剧情缺失；不要仅因没有分镜、服装颜色或画幅而判定故事不完整。
3. 完整时返回 `assessment=complete` 和 `proceed_policy=normal`，直接建议 `story-analysis`，不要求用户先润色。
4. 存在关键缺失或矛盾时，明确指出缺项及其影响，返回 `assessment=needs_input` 和 `proceed_policy=waiting`。由主控展示“补充故事”“补全并润色”“沿用原文继续”的操作；不得自行补剧情。
5. 用户补充后对新版本重审；用户主动选择润色后交 `story-polishing`；用户明确沿用原文时，记录缺项和 `proceed_policy=user_accepts_gaps`，允许后续分析，不偷偷补写结尾或将评估改成完整。
6. 没有任何可识别的故事内容时，沿用原文不能产生可处理的输入，指出最少需要补充的内容。已有足够内容但存在叙事留白时，不因同一缺项反复阻塞。

## 创作阶段把关

- `review_creative`：回读已保存的创意稿，核对采用的故事版本、全部精确保留台词、关键情节和新增设定。素材回填后再核对真实图片、声音引用与创意是否一致。
- `review_storyboard`：检查内容覆盖、动作顺序、情绪转折、台词落点和结尾表达。时长估算与实测冲突交回分镜和声音模块修正。
- `review_final`：结合实际媒体检查证据判断故事是否完整呈现。只看分镜不能宣布成片叙事通过；未能查看的内容标为未检查。

## 返回主控

按[统一协议](../../contracts/runtime.md)返回 `DirectorReview`：操作、目标版本、逐项结论、缺失信息、精确保留项、继续策略和下一步。完整故事审查可返回 `done`；需要用户决定时返回 `waiting_user`。

报告交主控保存。需要可见审阅记录时用 `jht_document_save` 保存已取得产物引用的报告。导演只给出创作意见，不代替用户选择润色，不直接提交图片、音乐或视频任务。
