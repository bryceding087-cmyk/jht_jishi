# 剪辑、字幕与成片合成

输入为采用的片段、提前生成的整片 BGM、其他音轨、分镜顺序、精确字幕和品牌文案、输出规格及后期授权。已有成片仅修改文字时直接从旧时间线开始。

主控指定操作 `plan_timeline`、`render` 或 `revise`。`plan_timeline` 可以在音轨未齐时使用，只整理实际剪辑草稿、标明声音需求并返回；`render` 与 `revise` 才要求所有采用文件齐备并执行合成。

## 执行

1. 用 `jht_media_inspect` 获取实际媒体参数和必要长度。确认时间线引用的资产存在，不把文件名或供应商临时 URL 当作稳定资产。
2. 建立视频源裁切、成片区间、转场重叠和音轨区间。按故事顺序排列；独立片尾增加时长，叠字层不额外占时长。比较实测长度与 `PlannedTimeline`，用 `jht_timeline_save` 保存实际剪辑草稿。`plan_timeline` 至此返回，供声音补齐和已有 BGM 对齐，不提前渲染，也不默认要求重新作曲。
3. 明确原生声音与独立配音的取舍，保留需要的环境音，设置对白、旁白、BGM 音量和淡入淡出，避免双重人声或音乐掩盖台词。
4. 有字幕需求时用 `jht_subtitles_align` 将核对后的台词对齐到采用音轨；传入正式音频或视频原声的媒体来源、轨道和裁切区间，检查漏句与时间码。无需字幕时不新增对白字幕，但仍保留用户要求的品牌文字层。
5. 单独建立品牌文字和 Logo 层：完整文案、出现区间、位置、字体与动画。字体或字符不可用时在合成前报告并选择可用字体，不让视频模型生成精确文案。
6. 更新并保存完整 `Timeline`；在其资源齐备、时间区间有效、音轨和输出规格明确后调用 `jht_render_submit`。
7. 通过 `jht_render_query` 取得成片。将实际输出交 `quality-review` 检查，通过后由主控调用作品交付工具。

## 返回与检查

按[统一协议](../../contracts/runtime.md)返回时间线版本、字幕、文字层、渲染任务和 `RenderArtifact`。渲染成功只代表文件产生，不替代成片验收。

渲染失败保留全部上游媒体，仅修复受影响参数或轨道。总时长变化使声音、字幕或品牌阅读时间不足时，返回具体冲突范围。
