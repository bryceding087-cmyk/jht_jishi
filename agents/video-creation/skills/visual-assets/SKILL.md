# 视觉素材准备

输入为创意版本、素材需求、用户附件、模型方案和本批次授权。此 Skill 只处理视觉素材；声音交给 `voice-production` 或 `music-production`。

默认操作为 `prepare_visuals`。生成前请求主控通过 `canvas-management` 建立或复用本轮素材节点，保存需求 ID 到节点 ID 的对应关系；占位节点标记待生成，不预填假的素材文件。

## 执行

1. 用 `jht_assets_search` 查找角色、场景、Logo 和已有参考。核对类型、实际内容与当前风格；复用不等于只按文件名匹配。
2. 用户新附件经宿主上传控件取得凭据后用 `jht_assets_import` 入库。已有资产直接绑定，不重复上传或公开受保护素材。
3. 先准备风格参考，再生成必要角色与场景。独立请求可并发；统一使用当前确定的风格与人物约束。按需要生成单视图、设定图或四视图，不固定图片数量。
4. 调用 `jht_images_generate` 时传已选图片模型、明确提示词、真实参考资产和已保存的目标节点。节点关联由工具层登记，不把额外字段透传给现有图片 API。按实际能力限制参考图数量、尺寸和水印选项。
5. 用 `jht_images_query` 取得真实任务结果和资产。调用返回受理时登记等待，不立即标为素材完成。
6. 将实际图片交 `quality-review` 检查身份、服装、风格和可用于后续生成的程度。通过后可用 `jht_characters_save` 保存本次角色；未经用户要求不覆盖跨项目共享角色。
7. 更新 `AssetManifest`，记录用途、来源、节点、实际资产与路径、版本、检查结论和依赖。成功结果绑定原目标节点；图片和音色素材全部就绪后，交创意模块回填文档，再统一自审和整理画布。

## 返回与检查

按[统一协议](../../contracts/runtime.md)返回实际资产、待完成任务和缺失项。失败只影响对应素材；其他成功素材继续保留。

Logo 和精确文字优先使用真实品牌素材或后期文字层。生成图里的文字不能代替用户要求的品牌标准。当前所选方案没有使用的推荐素材标为可选，不因此阻塞分镜。
