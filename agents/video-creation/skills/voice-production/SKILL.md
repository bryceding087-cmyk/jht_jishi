# 音色与配音

有对白、旁白、音色要求或口型同步需求时使用。输入为台词、人物设定、目标时长、声音偏好、可用音频与模型能力。

支持 `prepare_anchors`、`generate_lines` 和 `complete_required_audio`。素材阶段用 `prepare_anchors` 生成或复用音色参考；默认在分镜确认后的声音准备中使用 `generate_lines`，存在具体时长风险时可按主控确定的授权范围提前试读；后期只补齐尚未完成的必要音轨。

## 执行

1. 明确当前操作是声音设定与试听，还是生成完整台词。用 `jht_assets_search` 检查用户录音、已有配音和声音参考。
2. 为每个说话人建立稳定声音映射，包括旁白。`prepare_anchors` 在本轮音频节点上关联声音需求，用 `jht_voice_prepare` 生成代表性试听，必要时以 `jht_audio_query` 查询完成，记录实际声音 ID、锚定音频资产、受保护路径和支持能力。复用已有合格锚定音频时不重复生成。
3. 结合模型能力确定原生对白或独立配音。视频模型“能生成声音”不等于能够固定人物音色或逐字正确朗读；重要台词仍需检查。
4. `prepare_anchors` 完成后返回声音素材供创意回填，不自动生成全部正式台词。分镜确认后，或取得范围明确的提前试读授权后，独立配音用 `jht_speech_generate` 提交已采用台词和音色，再用 `jht_audio_query` 获取结果。提前试读不扩大到未授权台词，合格音频后续直接复用。没有台词或用户指定无配音时标为不适用。
5. 对每条正式配音记录台词 ID、音频资产、实测时长、停顿和发声人。交 `quality-review` 核对漏句、说错人、语速及音色一致性。
6. 音频超出规划时长时返回镜头调整建议。需要口型同步的镜头等待正式音频和可用同步能力；不通过悄悄删词或过度加速来满足时长。
7. 后期采用独立配音时标明原生人声保留、替换或静音方式；旁白、对白与环境声分别列轨。

## 返回与检查

按[统一协议](../../contracts/runtime.md)返回 `VoicePlan`、`AudioManifest`、待完成任务与时长问题。试听完成不能标为正式配音完成。

音色参考作为本轮音频素材回填创意文档并接受 G2 审阅；正式台词随其采用分镜与声音版本登记。只有声音 ID 而没有音频时，不宣称锚定音频已生成；服务不支持试听时说明具体情况和用户接受的声音方案。

当前服务未接入时可复用用户已有音频或明确可用的原生声音路径。若这些路径不能满足用户要求，向主控返回缺失能力，保留文稿和声音方案。
