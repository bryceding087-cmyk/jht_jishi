# 分镜规划

输入为已回填实际素材且通过 G2 的创意版本、内容清单、素材与声音方案及模型能力。仅做分镜的任务使用用户指定的文档范围例外。使用[分镜模板](../../templates/storyboard.md)。

## 执行

1. 确认主控已通过 `canvas-management` 保存文本和脚本节点。需要借助现有功能时调用 `jht_script_generate` 的 `script` 动作；该调用会保存脚本，须使用最新项目版本。
2. 将返回分镜视为草稿，逐项核对原文约束。当前服务倾向生成 4–12 镜不是业务硬目标；根据剧情修订结果，用 `jht_script_save` 保存，不为凑数量损害叙事。
3. 为每段维护稳定 `shot_id`，与可变化的 `scene.index` 分开。写出画面、动作、构图、景别、光线、运镜、连续性、台词 ID、素材 ID 与声音路径。
4. 安排动作和对白的先后与重叠，预留停顿和片尾阅读时间。使用正式音频时采用实测长度；未取得时标记待复核，不能宣称准确锁定时长。存在具体的时长风险时，由主控在已授权范围内提前试读相关台词，再修正分镜；不因默认阶段顺序形成互相等待。
5. 检查模型单次时长与参考能力。需要拆段时保留故事节奏；有口型或上一段尾帧依赖时写出依赖关系。
6. 可用 `jht_script_generate` 的 `resources` 动作辅助分析需求，但其可选建议不得自动成为新的强制上传要求；已有正确绑定继续复用。
7. 将扩展数据保存在 `Storyboard`，同时形成 `PlannedTimeline`：各段计划起止秒、对白区间、转场、片尾及总时长，不依赖实际视频文件。将现有支持字段通过 `jht_script_save` 写回，提交缺失素材或前置配音需求。

## 返回与检查

按[统一协议](../../contracts/runtime.md)返回分镜、计划时间线、内容覆盖表、镜号映射及待校验项。每条精确保留内容均能找到位置，计入转场与片尾后的时长符合方案。

下一步合成提示词并交导演与质量检查，G3 有效后进入整片 BGM 和正式声音准备，再生成视频片段。声音实测导致分镜变化时更新计划时间线并复核相关确认；不得一边使用旧版音乐时间线一边提交新版镜头。
