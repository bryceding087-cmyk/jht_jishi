# 创意设计

输入为 `StoryAnalysis`、用户风格要求、可复用参考和模型约束。使用[创意模板](../../templates/creative-brief.md)组织产物，按项目规模省略不适用部分。

操作分为 `draft` 与 `bind_assets`。`draft` 撰写创意并回读自审；`bind_assets` 在素材就绪后更新现有文档的绑定表，不重新改写故事或角色设定。

## 执行

1. 确定主题、受众、情绪变化和起承转合，说明观众应理解的人物变化与品牌表达。
2. 描述整体画面风格、色彩、光线、人物设定和场景关系。原文未给出的外貌、服装、年龄等标为创意建议。
3. 设计声音方向：人物声音、旁白、环境音、音乐及静默区间。需要口型同步时记录前置音频依赖，不承诺尚未确认的工具能力。
4. 建立素材需求，标明文件类型、用途、来源优先级、关联情节及是否为当前方案必要素材。风格参考可以复用，避免无目的地生成多套图片。
5. 交主控保存 `CreativeBrief`，取得引用后用 `jht_document_save` 创建可审阅文档。回读保存后的版本，检查人物、情节、全部精确保留项及目标时长，再交导演把关；通过后才进入素材制作。
6. 镜头级参数留待分镜阶段，不在创意阶段固定无法验证的镜头时长。需求清单此时可有待生成项，但不能编造素材路径。

## 素材回填

`bind_assets` 接收实际 `AssetManifest`、`VoicePlan` 和节点映射。将风格、角色、场景、道具及每位说话人的锚定音频逐项写回：需求 ID、实际资产 ID、声音 ID、节点 ID、受保护访问路径、用途和版本。

路径与 ID 必须来自工具回执，不能把预计文件名写成已存在文件；路径过期时凭稳定资产 ID 刷新。保存新的文档版本，只增加绑定修订，不使同一创意内容下已生成素材失效。回读绑定表后交导演和素材质量检查，再整理本轮画布并展示 G2。

## 返回与检查

按[统一协议](../../contracts/runtime.md)返回创意、素材需求或回填结果、假设和检查记录。初稿通过后进入素材阶段；回填稿通过且画布整理完成后才进入 G2。分镜读取回填后的采用版本。

故事需要重新组织或删改关键台词时返回明确差异，不把修改悄悄藏在创意稿中。用户只调整视觉风格时保持原剧情约束。
