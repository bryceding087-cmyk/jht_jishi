# 质量检查

在阶段产物产生、媒体任务完成或用户报告问题时使用。输入为目标产物及版本、原文约束、用户已认可的取舍和必要检查范围。

导演负责故事是否完整和创作表达，本 Skill 负责内容映射、文件与媒体证据；两者的结论分开保存。可按 `review_assets`、`review_audio` 或片段/成片检查范围执行。

## 执行

1. 对创意、分镜和提示词做文本检查：重要情节、所有对白与旁白、品牌文案、动作顺序、时长安排、素材绑定及模型能力。
2. 对图片、音频、片段和成片使用 `jht_media_inspect` 支持的检查。检查方法包括元数据、抽帧、转写和实际视觉/音频审阅；只选择当前任务需要的方法。
3. 按对象检查：参考图的角色与风格；每位说话人的锚定音频与素材回填关系；正式配音的台词、说话人和长度；BGM 可用性；片段的身份、动作和声音；成片的顺序、转场、混音、字幕和品牌层。
4. 对每项记录 `pass`、`fail` 或 `not_checked`，附产物版本、时间区间和证据。转写正确不代表口型正确，任务成功不代表媒体内容正确。
5. 必需检查无法自动完成时，向主控返回需要人工查看的具体画面或试听区间。用户对该版本的真实检查可补充证据，但不能证明缺失文件可播放。
6. 素材自审核对创意文档、素材清单、实际路径与本轮节点是否一致；分镜检查核对输入为已回填的采用版本。精确台词发生变化时追溯到用户采用的工作稿，不能误用未采用草稿。
7. 输出最小修复建议：更换参考、重做某段、重录一句、修改字幕或重跑渲染。质量检查本身不提交新的付费生成。

## 返回与检查

按[统一协议](../../contracts/runtime.md)返回 `QualityReport`，区分阻断交付与可接受的普通问题。主控按用户是否接受具体取舍更新要求，并对新版本重新检查。

检查覆盖范围必须明确。完整视频的必需检查未完成时不得给出整片“通过”，也不能仅因用户要求尽快交付就把未知项改成通过。
