# 画布与资源绑定

在阶段产物保存、素材绑定、展开分镜、视频提交或作品交付时使用。输入为真实产物引用、项目版本和已存在的映射。

`prepare_resource_nodes` 在素材生成前建立本轮图片和音频节点，记录需求映射与待生成状态；`organize_batch` 在素材回填与自审后重新读取画布，整理本轮已生成节点。生成过程中的结果绑定可增量同步，但不能用“节点已创建”冒充“素材全部就绪”。

## 执行

1. 用 `jht_project_context` 读取最新画布和用户手动修改。识别 Agent 管理的节点与连线，保留其他内容。
2. 将原始剧情、当前采用故事和创意保留各自来源并映射到文本节点，将分镜映射到脚本节点，图片映射到图片/道具或角色节点，锚定声音、正式配音和 BGM 分别映射到音频节点，片段与成片映射到视频素材节点。
3. 使用 `jht_canvas_apply` 提交语义补丁，由工具层合并成现有 Project 结构。现有节点类型为 `prompt`、`script`、`asset`、`prop`、`character`、`audio`、`video-asset`、`video`。宿主使用 `agent_key`、`agent_stage`、`agent_layout` 元数据按故事分析、创意设计、参考素材、分镜规划、镜头生成、片段与声音、合成与交付分区排布，画布渲染阶段标题及关联箭头，无须创建新的节点类型。
4. 保持脚本资源的 `asset_id`、文件类型和 `scene_indices` 与实际采用素材一致。记录稳定片段 ID 到显示镜号的映射，重排后同步更新。
5. 需要生成视频时调用 `jht_canvas_expand_storyboard`，创建或复用对应 `video` 节点，保存 `scriptSourceId`、`settings.script_scene_index` 和连线。
6. 校验视频有效输入。后端会从脚本继承提示词和时长，从图关系解析参考图；单独修改请求中的 `asset_ids` 不能修正错误连线。当前音频和视频节点不能直接作为生成参考输入。
7. 返回新项目版本、节点映射和宿主计算的输入指纹。若节点上限或版本冲突阻塞，保留补丁并返回明确问题。

## 返回与检查

按[统一协议](../../contracts/runtime.md)返回 `CanvasProjection`。生成前的脚本、提示词、素材图与确认版本必须一致；用户可见的预览与实际提交输入一致。

重复同步复用已有节点与素材，不无限添加副本。流程关联使用 `relation: agent-flow` 虚线，仅用于展示来源与产物关系，不进入图片、配音或视频生成的输入解析；真实生成输入保留实线。整理时保留非 Agent 节点与手动连接，自动更新保留用户已移动的坐标。用户主动点击“整理画布”时才重新排列该 Agent 的全部节点。旧网格项目首次读取时自动迁移，不重新请求模型或改写素材。

素材阶段的整理范围限于本轮需求对应的节点及其新结果。将节点 ID、资产 ID 和真实访问路径返回创意回填流程；纯布局变化不改变创意内容版本，也不触发媒体重新生成。
