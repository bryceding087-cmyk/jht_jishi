# 项目上下文

在新建、续作、进度查询或目标项目发生变化时使用。输入为可信会话、用户消息、当前项目 ID 和可选运行 ID。

## 执行

1. 调用 `jht_project_context` 读取当前项目、节点、相关素材、角色和已有任务摘要。优先使用对话当前项目，不因一句新剧情就自动另建项目。
2. 调用 `jht_run_load` 恢复运行、确认、产物版本和在途任务。没有运行时返回初始化建议，交主控创建检查点。
3. 没有当前项目且需要保存本次制作时，依据剧情给出项目名并用 `jht_project_create` 创建；多个候选项目无法判断归属时返回一个澄清问题。
4. 区分用户新提交剧情、历史案例、已有脚本、模板和已生成媒体。新故事交主控以 `StorySource` 保留原文，初始化 `working_story_ref`，再交导演检查。模板只能提供结构，不能覆盖用户的具体台词、品牌和规格。
5. 输出当前可复用产物和首个需执行步骤。对正在运行的媒体任务返回任务引用，由对应生成 Skill 查询；不重复提交。

## 返回主控

遵循[统一返回协议](../../contracts/runtime.md)。返回 `ContextSnapshot`，包含项目及版本、运行 ID、意图、素材与节点摘要、现有确认和待恢复任务。新故事先建议 `director`；已有故事检查和有效用户选择则按当前阶段续作。

## 完成检查

项目归属明确；原始输入有来源；当前项目、运行和素材引用来自真实工具响应。读取不到的内容列为未知，不拼凑资产或项目 ID。

工具失败时保留用户输入并返回具体缺失项。仅缺少画布分组或运行存储时，允许继续形成可保存的创作草稿，但不得伪称已创建运行或节点。
