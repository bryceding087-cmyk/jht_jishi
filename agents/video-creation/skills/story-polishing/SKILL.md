# 故事补全与润色

仅在用户点击“补全并润色”、明确提出润色要求，或已具体授权补全故事时调用。导演指出缺项、界面展示按钮、用户沉默或“你来定画面风格”都不能自动触发改写。

输入为当前故事引用、导演指出的缺项、用户改写要求、精确保留项和明确授权范围。普通措辞润色与新增情节分别标记；用户只授权措辞调整时，不借此补写人物动机或结尾。

## 执行

1. 核对来源版本和用户授权，保留原始故事。确定操作为 `wording_only` 或 `complete_and_polish`，对未获准改动的台词、事实、人物身份和品牌文字建立保留清单。涉及付费文本调用时，由主控复用已有模型与费用授权，必要时先调用 `model-budget` 补齐该次调用依据。
2. 调用 `jht_story_polish`，要求返回修改稿、逐项差异、补充设定和仍未解决的问题，不覆盖项目中当前采用的故事。
3. 回读原稿与修改稿。逐字核对保留清单，检查新增剧情是否在用户授权范围内；违规修改先修正，不能直接下传到创意或分镜。
4. 将 `StoryDraft` 交主控保存，并可用 `jht_document_save` 展示修改稿与差异。默认让用户选择采用修改稿、继续编辑或保留原稿；已有“润色后直接继续”等明确授权时，按该授权采用并展示实际修改。
5. 只有稿件被采用后才更新 `working_story_ref`，重新交导演审查，再进入时长分析。未采用的稿件保持草稿状态，不影响正在使用的故事和下游产物。

## 返回与检查

按[统一协议](../../contracts/runtime.md)返回修改稿、原文引用、差异、保留项检查和待采用状态。若用户拒绝或撤销修改，保留原文并回到用户所选路径，不无限润色。

建绘通现有 `/api/prompts/polish` 的目标是视频提示词，不能直接用于完整故事补全。v0.3 由 `AgentService.polish` 加载本 Skill，通过已配置文本模型执行专用故事润色，保存独立草稿并校验原台词与品牌文字；采用后才进入下游。
