# 视频任务生成

输入为已授权的 `Storyboard`、`PromptSet`、`ModelPlan`、画布映射、预算、本批次镜头范围，以及已经就绪的 BGM 与前置声音或用户批准的例外。

## 执行

1. 检查实际节点、脚本与素材连线已保存，输入指纹与批准版本一致；不一致时交主控重新同步或处理修改，不能仅把正确提示词写进请求正文就提交。
2. 核对分镜确认、整片 BGM 准备和前置正式音频已完成，或有明确的无配乐、样片或制作顺序例外。BGM 留待后期混音，不作为当前不支持的音频参考传给视频模型。按尾帧等依赖建立队列，独立镜头在授权并发内执行。
3. 调用 `jht_video_generate`，一个片段对应一个稳定请求与任务记录。由工具层完成输入冻结、预算预留和去重，保存返回的实际提交参数。
4. 用 `jht_video_query` 或宿主完成事件更新状态。受理不等于完成；`blocked`、未知提交和失败分别处理。没有供应商证据时不编造进度百分比和剩余时间。
5. 成功片段交 `quality-review` 检查长度、人物、动作和声音。链接缓存失败时先调用 `jht_video_cache` 修复下载；不重新生成已经成功的任务。
6. 对采用的片段调用 `jht_video_save_asset`，保存素材 ID、实测信息和与镜头的关联。缓存文件和素材入库分别记录。
7. 返回本批次状态；全部采用片段可用后进入后期。失败只触发相关任务的修复，不重做成功批次。

## 返回与检查

按[统一协议](../../contracts/runtime.md)返回 `VideoBatch`、待查询任务、失败原因和素材引用。任务输出以稳定镜头 ID 归位，不按完成先后排序。

目前后端会重算输入模式与参考图，也没有客户端视频幂等键。对应工具层尚未补齐时报告不能安全提交的原因，不声称已有精确输入冻结或去重能力。配额不足、内容拒绝和普通超时不能采用同一种重试策略。
