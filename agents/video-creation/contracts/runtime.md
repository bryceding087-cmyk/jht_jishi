# 建绘通 Agent 运行说明（v0.3.0）

运行层位于 `agent_runtime.py`，由 `app.py` 注册；合成器位于 `agent_media.py`。用户在建绘通登录后，通过对话创建视频项目。它不依赖外部编程助手，也不通过外部桌面应用执行工具。

## 加载和调度

服务启动时读取 `agent.yaml`、16 个 Skill 的文件路径与工具能力目录。创作请求加载 `AGENT.md` 和当前相关 Skill，将模型返回的 JSON 校验后保存。主控使用确定性的阶段调度调用内部 Python 业务函数，模型不能自行执行代码、读写任意路径或指定其他账号。

`contracts/tools.yaml` 中的 33 个 `jht_*` 名称是逻辑能力名称。`binding.implementation` 指向实际方法，`binding.status` 标明 integrated、limited 或 unavailable。它们不是 33 个独立 HTTP 接口，也不是直接交给模型的函数调用 Schema。各 Skill 的通用产物协议作为创作约定；实际模型 JSON 格式由对应阶段的任务提示词和校验代码限定。

默认流程：导演检查 → 时长分析 → G1 参数 → 创意及回读自审 → 视觉和音色 → 回填与 G2 → 分镜及 G3 → 正式配音 → 节拍表和整片 BGM → 视频片段 → 本地合成 → G4 观看检查 → 完成交付。原稿缺项时先出现 S0，润色仅在主动选择后生成，草稿被采用前不用于下游。

当前默认引导式流程保留 G1/G2/G3/G4，尚无无监督全自动授权模式。参数卡也可用自然语言回答。只要分镜时跳过图片、音频、视频和合成。

## HTTP 接口

所有接口继承现有登录认证；写请求需同源 Origin。运行记录按账号隔离，底层项目、模型和素材继续使用当前产品的团队工作区。

| 接口 | 用途 |
| --- | --- |
| `GET /api/agent/capabilities` | 版本、已注册 Skill、模型、逻辑工具能力及 FFmpeg 可用性 |
| `GET /api/agent/runs` | 当前账号的创作记录 |
| `POST /api/agent/runs` | 创建运行和项目，返回 202 及初始快照 |
| `GET /api/agent/runs/{rid}?after=序号` | 运行快照与增量事件 |
| `POST /api/agent/runs/{rid}/messages` | 追加消息、提交确认、暂停、恢复、重试或更新偏好 |
| `GET /api/agent/runs/{rid}/artifacts/{asset_id}` | 读取属于该运行的已保存文档版本 |

创建请求包含 `text`、客户端生成的 `request_id`、可选 `project_id`、`asset_ids` 和 `preferences`。同一请求编号携带不同正文返回 409。偏好包括比例、风格、目标时长、制作范围、配音、BGM、字幕及四类模型配置 ID。密钥始终留在原有模型配置服务。

消息使用 `request_id` 去重，包含 `text`、可选 `action`、`review_id`、`values` 和 `asset_ids`。确认必须绑定当前卡；过期卡返回 409，无效参数返回 422 且不消耗确认。支持 action：`pause`、`resume`、`retry`、`cancel`、`preferences`，以及当前卡提供的 `confirm`、`supplement`、`polish`、`continue_original`、`adopt`、`keep`。

## 数据与事件

沿用 SQLite records 存储，新增逻辑类别：

- `agent_run`：原文、采用稿、偏好、阶段、状态、审批、当前产物、媒体绑定、输入摘要和请求去重记录。
- `agent_event`：按运行递增序号记录 user、assistant、phase、step、review、review_resolved、artifact、task、media、progress、issue、delivery。
- `agent_operation`：操作标识、尝试次数、提交/成功/失败/无效/未知状态及任务回执。
- `agent_artifact`：保留版本的结构化载荷、可读正文、摘要和资产 ID。

文档保存为真实文本资产及对话 artifact，不为导演分析、自审、配乐方案、时间线等过程文档创建画布节点。画布仅保留可编辑的采用故事、分镜脚本和实际媒体。生成媒体使用原有 asset、image_task、audio_task、task 记录。成片作为 generated 视频资产入库，可在对话和素材库播放、下载。

run.status 包括 running、waiting_tool、waiting_user、paused、blocked、completed、cancelled。`completed` 可以表示用户只要求的分镜已完成；完整视频还必须有 render_asset 和 G4 确认。

## 幂等、暂停和恢复

`agent_dialogue.py` 根据当前故事、已保存产物和用户偏好组织关键阶段交流。现有文本请求可返回可选 `user_message`，用于简短说明故事理解和创作选择；完成数量、素材状态及下一步由宿主补充。可选文案缺失或不合适时使用本地说明，不新增模型请求或审批节点。普通助手消息通过净化后的 Markdown 展示。

每个运行同一时刻只有一个主控线程。用户在生成期间追加修改，会先保存修改要求，当前调用结束后再处理；连续修改按顺序合并，不并发修改同一运行。暂停停止后续提交，已经交给供应商的任务可能继续，不能承诺撤销计费。

图片、音频使用已有请求编号幂等；视频提交新增 request_id 和原始参数摘要。重放同一请求返回原任务，修改参数须新的请求编号。主控在提交视频前比较已确认的画布输入，再把冻结的项目快照传入业务函数，避免二次读取画布时使用未确认的输入。

服务重启将未结束的运行标记为 paused。恢复时首先读取操作日志与任务回执。有供应商任务编号的视频恢复 GET 查询，不重新 POST；图片/音频服务被中断且无法追回结果时，提示用户核对素材库和服务商记录后主动重试。未知文本请求不会在继续查询时自动重发；主动重新请求可能再次计费。

模型已返回但语义检查未通过时，主控将错误和上次结果反馈给文本模型，最多自动修正两次，保留有效媒体；仍失败才标记 invalid。自动修正属于新的文本请求，按服务商规则计费；媒体失败和结果未知的请求不自动重发。当前费用不可自动查询，不显示虚构积分或预算余额。旧运行因不支持的镜头时长而阻塞时，继续查询可复用原始文本结果，经本地规划适配后继续。

## 模型能力与规划适配

每次创作调用都注入 `model_constraints`：所选模型身份及能力，不传入密钥或认证地址。视频能力来自与提交接口相同的模型注册表，并与 Task 的 1–60 秒范围取交集。分析、创意、分镜及修订使用一致的约束；参数卡只展示所选视频模型支持的画幅。

`agent_planning.normalize_storyboard` 规范数字字符串、小数和缺省时长。不支持的镜头长度按可执行总长最小、片段数最少的顺序适配；超长镜头保留根 ID，续镜使用稳定的 `_part_N` ID 与 `continuation_of`。正式台词只挂在根镜头，允许音轨连续跨镜播放。分镜文档与画布同步保存适配后的时长。

AI Market 要求上游可访问的 HTTP(S) 参考图。本地图片继续留在创意和素材库中，其设定写入视频提示词；脚本资源和视频接线均排除不能传输的图片，分镜文档说明该行为。不会切换用户所选的服务商或模型。

## 画布和修改

节点 ID 从运行及产物角色稳定派生。先读最新项目、按节点合并、再用原有项目 revision 做 CAS；409 时最多重读三次。已有位置保留，新增节点按规则排列。嵌入画布只允许建绘通同源页面加载，手动改动生成字段后需同步要求并再次确认。

Agent 画布使用与普通画布相同的节点、贝塞尔连线和操作工具，不显示阶段分组、流程说明线或额外的“制作流程”工具栏。待执行镜头保存在脚本中；审批时通过不写入数据库的 `video_input_project` 计算完整输入，开始执行某镜头时才物化其视频节点。片段资产回填该生成节点的 `assetId`，不再创建 `result:shot_*` 副本；合成成片仍单独显示。

布局版本 2 在打开旧项目时安全迁移：合并生成/结果卡和同一图片的角色副本，保留原生成参数与手动坐标，普通连接重定向并去重。过程文档只有在正文与当前/历史 artifact 匹配时移除；被用户改写的文档转为普通文本节点。历史真实素材、手动添加节点和其他项目内容保留，迁移不会生成媒体。

仅修改片尾重新合成；修改具体镜头保留其他视频和正式配音，再确认受影响镜头。调整参考素材时保留未变化绑定。更换模型或制作参数按依赖使下游结果失效。大幅改剧情重新检查采用稿，原始故事和历史产物保持可追溯。

## 合成与质量

启用整片音乐时，成片使用前置音乐阶段保存的 `run.bgm.asset_id`，整条音轨贯穿时间线。视频片段自带音轨静音，正式配音独立混入；有正式配音时 BGM 音量为 0.24，无正式配音时为 0.85。短 BGM 循环、长 BGM 裁剪，仅整片结尾淡出 0.8 秒。缺少 BGM 时先返回音乐阶段，关闭音乐时不混入历史 BGM。合成缓存包含混音版本和时间线摘要，旧混音结果不会被新规则错误复用。

FFmpeg 仅接受素材库里已登记的本地文件。它实测时长，统一帧率、尺寸和音轨，拼接视频、混音、添加 ASS 字幕和片尾淡入，输出可播放的 H.264/AAC MP4。镜头不足以容纳配音时，自动延长或添加符合模型能力的连续镜头，复用完整配音，不删台词或加速。自动调整前后检查画布输入，用户手动修改仍需同步确认。BGM 可按时间线循环与淡出。

支持 16:9、9:16、1:1，当前导出分别为 1280×720、720×1280、960×960。初始规划最多 40 镜，自动拆分后最多 80 镜、8 个视觉参考和 8 位说话人，故事输入 24000 字符；规划及合成总长上限 20 分钟，用户指定目标时长范围 8–600 秒，单镜仍受实际视频模型能力约束。

自动检查覆盖文件、时长、尺寸、台词到镜头的覆盖和输入版本。字幕按每条正式音频的区间排布，未接入逐字 ASR/强制对齐；没有自动口型同步或画面内容理解。最终由用户实际播放检查，G4 确认后交付。

## 部署边界

当前使用单个 Uvicorn 进程内的后台线程和锁，适合本项目现有单服务部署。不要使用多个 worker 共享该运行引擎；扩展为多进程需外置队列和数据库级任务租约。进程重启可恢复已记录的产物和任务，但本地 FFmpeg 中断后需要重做该次合成。

`JIANHUITONG_FFMPEG` 可指定 FFmpeg，否则优先系统 PATH，再使用 imageio-ffmpeg 随包程序。Linux 部署应提供支持中文的字体（例如 Noto Sans CJK SC），以正确显示中文字幕。
