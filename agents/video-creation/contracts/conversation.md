# 建绘通项目对话协议

面向用户的入口是建绘通项目内对话。主控通过 `jht_ui_present` 展示消息、文档、媒体和确认卡；宿主将用户文字、卡片选择及附件作为新的项目事件返回。

## 输入事件

宿主提供 `message_id`、文本、附件资产引用、当前项目、关联 `review_id`（如有）与时间。附件从建绘通上传流程获得资产引用；模型不读取用户电脑上的任意文件路径，也不把外部地址自动公开给生成服务。

输入可为新剧情、确认、修改、主动润色操作、进度查询、续作、暂停或取消。一条消息可同时包含确认与修改，优先处理修改对版本的影响；不能把“确认，但人物换成女主角”视为批准旧人物方案。

## 展示卡片

| 类型 | 内容与用途 |
| --- | --- |
| `message` | 简短解释当前结果或处理方式 |
| `progress` | 阶段、已完成/总数、实际任务状态和可打开的产物 |
| `artifact` | 文档、分镜表、素材预览或声音试听，绑定版本 |
| `question` | 缺失的必要参数、推荐选项和影响 |
| `review` | 对具体方案的确认，包含费用与范围 |
| `issue` | 失败或阻断原因、已有成果和可选修复 |
| `delivery` | 成片预览、下载、实测规格与继续修改入口 |

确认卡含 `review_id`、`gate_id`、`artifact_refs`、`summary`、`choices`、`recommended_choice`、`cost_scope` 和 `invalidated_by`。默认选项只用于展示；没有用户提交或既有明确授权，不得自动视作确认。

## 默认确认节点

### S0：仅在需要时出现的故事处理选择

导演先判断故事能否进入制作。完整时直接进入内容量与时长分析，不强制润色；有关键缺项或矛盾时，指出具体内容与影响，展示以下操作：

| 操作 ID | 用户界面 | 后续行为 |
| --- | --- | --- |
| `supplement` | 补充故事 | 用户补充文本，保留来源版本，导演重新检查 |
| `polish` | 补全并润色 | 按用户授权范围调用故事润色，展示草稿与差异 |
| `continue_original` | 沿用原文继续 | 记录用户接受的缺项，按原文进入分析，不自行补写剧情 |

按钮通过 `question` 或 `review` 卡承载，绑定 `gate_id=S0`、故事版本和 `DirectorReview`。用户在文字中明确提出同等要求也可生效；仅展示入口、预选按钮或等待时间结束不构成操作。已有具体的故事改写授权可复用，不重复要求用户点击。

润色结果默认展示采用修改稿、继续编辑或保留原稿的选择，绑定 `StoryDraft` 版本。用户已说“润色后直接继续”时，保真检查通过即可采用并展示差异；一般的“人物、风格你来定”不覆盖故事补全。尚未采用的修改稿不替换 `working_story_ref`。

沿用原文不代表缺项消失。后续文档保留该取舍，导演不因同一缺项反复阻塞；只有输入为空或完全无法识别制作对象时，请求最少必要信息。

### G1：参数与初始制作范围

展示从剧情推导的时长范围、画幅、风格方向和初始模型/费用方案。只询问尚未明确且影响后续的项；用户已说“做 16:9 的 60 秒写实片”时直接使用，不再询问同样参数。

参数可与初步创意一起展示，不要求空等。风格、服装等可逆的普通创作选择可提出建议并继续；生成付费素材前确认本次授权是否已覆盖该费用范围。

### G2：创意与参考素材

展示已回填素材的创意新版本、实际角色场景图、角色与旁白音色锚定音频及对应画布节点。素材自审与本轮节点整理完成后再展示；说明真实已就绪项和用户接受的例外。选项建议为“按此继续”和“修改方案”。

如果用户事先授权“你来定风格和人物，直接制作”，记录授权并继续，不机械弹出此卡要求再次点击。

### G3：分镜与生成策略

展示每段内容、时长、对白/旁白、参考素材、采用模型、估算费用和生成策略。用户可以全部生成、先做指定样片，或修改分镜。样片仅在有助于当前项目时提出。

分镜可在明确标注台词估算与复核条件后审阅；不要求所有正式音频已生成。某段有具体的时长风险时，主控可在已有授权内先试读，或只请求该段试读范围的决定，再修订分镜。不能形成“必须先确认分镜才准试读、又必须先试读才准确认”的循环。

“全部生成并完成成片”覆盖该版本、所选模型和费用范围内的 BGM、正式声音、视频片段和正常后期。确认后先按分镜时间线准备整片 BGM 与前置配音，再提交视频批次；合成阶段对齐实际长度。生成期间持续展示结果，不在每次保存或正常后期前重复询问。

用户只要无音乐样片、仅要分镜或明确要求先看某个视频片段时，按该范围执行并记录顺序例外，不因默认 BGM 顺序扩大任务。

## 确认的有效范围

确认绑定具体产物版本和约束。后台文字润色、换模型、改变人物造型或超出预算使相关确认失效；不影响内容的节点位置调整不使创作确认失效。

自然语言“确认”只在存在唯一可判断的待确认事项时接受。多张待确认卡无法确定指向时，仅澄清当前指向，不要求用户重答全部问题。历史案例中的确认不作用于本项目。

## 修改与续作

用户说“最后字幕换一句”时，先复述采用的新文案并定位品牌层，执行局部更新；不重新生成全部镜头。用户说“师傅看起来太年轻”时，展示受影响人物参考和片段，再按修订范围执行。

查询进度使用最新运行与任务状态；回答后继续已授权任务。对话关闭不是取消。暂停停止新提交，取消按供应商能力处理在途任务，两者均保存恢复信息。

## 无法继续时

指出缺失的具体能力及它影响的步骤，附已完成产物。例如：“分镜和 5 段视频已保存，当前还缺少成片合成服务，因此尚未生成可播放的整片。”不要用内部调用栈替代用户能理解的说明。

额度不足时给出与当前方案对应的批次、规格或时长调整。工具不支持音色锚定时，说明可用声音方案；没有用户指定的声音需求时，不自行制造额外确认。

## 最终交付

展示成片和下载入口、实测长度与规格、版本号和采用的品牌文案。说明需要用户了解的实际限制；创意、分镜与片段作为可展开的附件，保持对话主体简洁。

用户可用自然语言继续修改，宿主将修改作用于这份交付版本。最终确认的目的为继续修改或验收，不能用展示交付卡来替代播放和必要的媒体检查。
