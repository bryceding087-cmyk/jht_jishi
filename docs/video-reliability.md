# 建绘通视频任务与界面更新（video-reliability-1）

适用于已经安装 market-login-1 和 proxy-origin-1 的 jht-app。本更新无需外网或新依赖，修改 14 个代码/前端文件并重启应用。

## 本次四项修复

1. 集市连接成功提示显示 3 秒，再向上移动 12px、以 0.3 秒渐隐后关闭。错误和连接中提示保留，便于重试。
2. 视频取得供应商任务 ID 后显示“已提交，正在排队或生成”；超过 2 分钟显示“本次生成较慢，仍在处理中”。取消旧的固定 120 次查询后判失败，改为后台按 5/10/20 秒间隔查询，临时错误退避至最多 60 秒。查询只使用原任务 ID，不重发生成 POST。只有明确的上游任务失败才记为生成失败；授权失效保留原任务并提示重新连接。
3. 左下用户区将挤成竖排的“重新连接”改为固定尺寸图标按钮，悬停提示、无障碍名称保留。姓名单行省略，部门最多两行；完整信息仍可悬停查看。
4. 新生成视频下载到本地后自动登记为当前用户的生成素材，关联原任务和项目，复用本地视频文件。自动保存与手动保存不会重复创建素材；保存暂时失败保留生成成功状态，并重试保存。

## 上传执行

将两个文件上传到服务器 /tmp：

- jht-video-reliability-20261018.tar.gz
- jht-video-reliability-20261018.tar.gz.sha256

逐条执行：

```bash
cd /tmp
sha256sum -c jht-video-reliability-20261018.tar.gz.sha256
tar -xzf jht-video-reliability-20261018.tar.gz
cd /tmp/jht-video-reliability-20261018
bash apply.sh
```

脚本先校验包和文件版本，备份后更新，再重启 jht-app 并检查健康、集市入口和 HTTPS 来源。不会清空用户、项目、素材或模型配置。建议等待正在生成的任务完成后安装；如确需重启，已保存的供应商任务 ID 会保留，可由原用户重新进入集市恢复查询。

成功输出包含 `SUCCESS: apply video-reliability-1; verified 14 files`，随后健康和代理来源检查均为 PASS。版本不匹配时保留报错，不要绕过检查。

## 验收

关闭集市内原建绘通页面，重新从 `https://aimarket.hncig.cn:4193/market` 打开，必要时 Ctrl+F5。

- 顶部连接成功提示在第 3 秒开始向上渐隐，0.3 秒后消失。
- 左下角姓名、部门和重连图标排列正常，重连按钮可点击。
- 提交视频后切换页面，再打开原项目/对话，仍可看到原任务的最新状态；长任务不会因为旧的 120 次上限变为失败。
- 新视频生成成功后，进入素材库的视频分类可看到对应素材；反复打开项目或手动保存不会重复入库。

## 后台查询与恢复边界

页面关闭或页面会话到期后，正在运行的查询线程仍保留此任务专用的内存凭据，只允许查询该任务的固定 GET 地址，不能创建新任务或调用其他地址。它不会写入数据库、浏览器存储、安装包或日志；账号停用、模型 Key 被上游撤销后停止有效查询。

一次后台查询窗口最长 24 小时；超过窗口后保留任务并显示待继续查询，不标为生成失败。重新打开项目可继续 GET 原任务。服务器进程重启会清除内存 Key；集市任务需原用户重新进入获取当前 Key 后恢复，通常在下次状态刷新时继续（授权暂停有最多约 30–60 秒退避）。不会回退到管理员或其他人的 Key，也不会重新提交收费任务。

普通独立账号的在途任务可使用原配置恢复查询。首页对话和画布均接入恢复；未拿到供应商任务 ID 的不确定提交不会自动重发。

自动入库适用于本版本完成的任务，以及通过本版本恢复查询后完成的旧任务。之前已经结束但未保存的历史视频仍可使用已有手动保存功能。本次不批量重新下载所有历史视频。

视频下载或磁盘保存失败时后台先自动重试；仍失败则保留“生成成功、保存待重试”，后续查看任务时继续尝试。未成功下载到本地之前，供应商临时视频链接仍可能过期，这与生成失败区分显示。

## 回滚

```bash
cd /tmp/jht-video-reliability-20261018
bash apply.sh rollback
```

备份在容器 `/app/.deployment-patches/video-reliability-1/originals.json`。回滚代码后重启，不删除已自动保存的素材。新代码产生的 JSON 元数据保留。后续文件发生其他修改时，回滚会拒绝覆盖。

补丁保存在当前容器可写层，重启同一容器有效；删除容器并使用旧镜像重建后需重新安装各更新。桌面 jht_jishi 源码已同步，今后完整重建镜像将包含这些改动。旧镜像和此前更新包未被覆盖。
