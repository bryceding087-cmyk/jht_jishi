## 应用方式与适配边界

运行时通过 `studio_skills.load_skill_bundle` 加载仓库内审阅后的中文规则，用建绘通已选文本模型按批次执行，每批最多 6 个节点、最多并发 3 批；规则仍分别应用到每个节点。这是**适配后的技能调用**，不直接执行 SkillHub 上游 Python/Node 脚本，也不另设 AIPDD 模型通道。没有全局修改 Codex 的技能目录或技能源设置。已下载的原始资料保存在被 Git 忽略的 `work/skillhub-research/`，供本地审阅；部署只需要应用内的规则和清单。

用户已有剧本、风格、模型、参数与引用关系优先。保留有用的创作方法，排除与现有任务不符的固定 24fps/宽银幕/60秒/2K、口型百分比、成功率、自动截断、固定动漫风、额外批量生图、自动更换服务商、重复确认、强制英文和固定负面词库。技能网页和示例中的安装、配置、账号、网络、消息发送等命令不作为执行授权。

每次请求包含本批各节点的独立上下文：原始提示词、用途、模式、时长、原文引用、只读素材职责、相关角色/场景/道具定义、统一美术及公开模型信息。每项使用稳定节点编号对应结果，沿前置依赖找到相关身份；不发送全局模型配置、API Key、签名素材 URL 或其他作品的素材。

模型按本批节点编号返回各自的 `direction`，服务端逐项匹配并校验，拒绝重复编号、缺项和越界结果。服务端保留原提示词全文，追加一段执行指导，拒绝多余字段、空内容、新素材编号/标签和超长内容。容量预算包含生成时追加的已选视觉风格，按实际风格组合器验证 4000 字限制。调用前对全部节点检查容量，不为挤出空间静默删对白。语义约束仍由文本模型执行，结构校验不能证明图片或视频效果。

## 保存、恢复与手动编辑

- 依据节点输入、相关设计、所选模型、优化契约和实际技能规则内容计算摘要。每完成一个节点保存结果；相同输入再次同步不再请求文本模型。规则或相关输入变化会使对应缓存失效。
- 已收到但无效的结果最多修正一次；再次失败停止，保留剧本、已完成优化和原画布。读取超时或结果未知时不会自动重发，沿用原有明确重试流程。
- 全部节点完成后才提交完整画布。保存遇到版本冲突时只重新合并，不重新优化。服务重启可复用操作回执，并恢复已保存但尚未关联的确定 ID 画布。
- 同步仍保留用户的提示词、模型、布局、手动节点与分组。新的优化存为待核对方案，不冒充当前已应用内容；采用更新方案后转为已应用。
- 节点 `mujian.promptOptimization` 保存技能来源、规则摘要与输入/原文/最终提示词摘要。Studio 的 `prompt_optimization_progress` 供制作页显示真实逐项进度。

多个待优化节点合并为一次文本模型请求，每批最多 6 项；已有有效缓存的节点无需重新请求。无效结果可能增加修正请求，实际费用按所选文本模型计费。创建画布只整理文本与引用，不触发生图、生视频或音频调用。

## 验证

`tests/test_studio_prompt_optimizer.py` 验证原文、参数、引用与合并契约；`tests/test_studio_skills.py` 用临时数据库和模拟文本供应商验证每类节点、生成模式、缓存失效、暂停恢复、无效输出、未知结果、容量预检与并发合并。现有 Studio 与浏览器测试继续使用模拟供应商。真实出图、动作连续性、口型和成片质量需通过实际模型生成评估。
