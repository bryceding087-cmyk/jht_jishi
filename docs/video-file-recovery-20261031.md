# 视频文件保存与历史恢复更新

版本：`video-file-recovery-20261031-1`。

此前页面可以直接播放供应商的临时视频链接，即使建绘通服务器下载超时，用户仍可能看过视频。临时链接过期后，预览和下载同时失败；原来的重试只访问旧链接。

## 更新内容

- 恢复视频时，只查询原供应商任务 ID，取得可用链接后保存视频，不重新提交生成请求，不创建新的收费视频任务。
- 新任务记录原模型接口与凭据指纹；恢复时校验账号、配置和返回的任务 ID。集市任务由原提交者重新连接后恢复；官方个人模型的恢复不依赖原浏览器集市会话仍然在线。
- 下载完成后原子写入本地文件，首页、画布和资产库改用站内文件；下载响应长度不完整时不会标记为保存成功。
- 短暂超时、连接异常等最多尝试三次，两次自动重试分别等待 30 秒、120 秒。重试状态保存在数据库中，服务重启后继续；失败耗尽后保留明确错误，可由用户手动恢复。
- “恢复视频”接口立即返回 202，下载在后台运行，关闭页面不取消保存。重复点击不会同时重复下载。资产库下载按钮会等待保存结果；较慢时提示后台仍在处理。
- 已生成但未保存的视频明确标注“临时预览／文件未保存”，保存成功后显示“文件已保存”。不会再把媒体错误一律提示为“请重新生成”。
- 支持尝试恢复旧的失败记录、已清空临时链接但保留任务 ID 的记录，以及服务器本地文件丢失的记录。恢复沿用原记录、所有者与资产库归属。

本包累计包含前两版回调更新：视频提交等待 120 秒、提交结果待确认、火山与 MiniMax 官方回调。回调默认基础地址仍为 `https://aimarket.hncig.cn:4193`，不带 `/market`；环境变量 `JIANHUITONG_VIDEO_CALLBACK_BASE_URL` 可以覆盖，显式空值可关闭。

## 安装与回滚

支持当前源码基线、`account-video-update-20261029-1`，以及 `video-callback-update-20261030-1`、`video-callback-update-20261030-2`。无需逐个安装旧包。本包先校验所有目标文件，再备份更新；遇到未知版本停止，不覆盖额外修改。包不含真实模型密钥，不修改已有环境文件、数据库结构或用户素材。

等待正在生成的任务结束，将更新包和校验文件上传到服务器 `/tmp`，执行：

```bash
cd /tmp
sha256sum -c jht-video-file-recovery-20261031.tar.gz.sha256
tar -xzf jht-video-file-recovery-20261031.tar.gz
bash /tmp/jht-video-file-recovery-20261031/apply.sh
```

安装器更新并重启 `jht-app`，检查运行文件、健康接口和回调入口。完成后刷新页面，必要时 Ctrl+F5。

回滚：

```bash
bash /tmp/jht-video-file-recovery-20261031/apply.sh rollback
```

代码补丁保存在当前容器可写层。以后重新创建容器时，应使用包含本次代码的新镜像，或在重建后重新安装本包。视频文件仍存放在 `/app/data/uploads`，正式部署须保留 `jht-app-data` 持久卷及其备份。

## 恢复线上历史视频

1. 使用原账号重新打开集市中的建绘通。
2. 在生成历史中点开失败的视频，点击“恢复视频”。原任务不重新生成。
3. 页面显示“正在保存”，可以离开页面等待。恢复成功后显示“文件已保存”，再验证播放和下载。
4. 如仍失败，详情保留具体原因。服务器到视频存储服务的出口网络仍需连通；本包不会更改网络、代理、证书或防火墙设置。

如果供应商已经移除视频、任务查询不再返回可用地址，或者原模型凭据不可用，无法保证找回。旧记录缺少任务 ID 时只能尝试原链接。此前未配置回调且没有任务 ID 的提交超时，也不能由本包补发回调。

## 验证

隔离测试覆盖：过期链接更新、下载超时后的有界重试、服务重启、官方个人账号登出、集市原账号重新连接、错误任务 ID、配置变化、账号隔离、删除、文件丢失及完整性检查。真实 Chrome 使用模拟供应商与本地 MP4 验证 202 返回、状态提示、恢复后播放、下载字节一致及刷新后仍播放本地文件，不调用收费模型。

本地测试不代表生产服务器能访问视频存储地址。此更新包需部署后再恢复截图中的历史视频并检查网络。
