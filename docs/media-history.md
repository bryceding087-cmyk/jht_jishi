# 生成历史与资产库

图片、视频、音频的生成结果，以及上传、导入、视频截帧得到的文件，都先进入当前用户的「生成历史」。只有用户点击「保存至资产库」，记录才会出现在「资产库」。直接引用历史内容或添加到画布不会改变这个状态。

资产库是生成历史的收藏集合，复用同一条记录和同一份文件。资产卡片、预览和画布中的已收藏内容显示「移出资产库」按钮，点击只取消收藏，生成历史、文件、对话和画布引用均保留；移出后可再次保存。对话结果中的保存按钮在保存成功后显示「已保存至资产库」并置灰，光标保持普通样式。各入口同步当前收藏状态，重复保存不产生副本，也不重新调用生成模型。已有文件和引用保留；旧记录没有手动收藏标记时仍可在生成历史中找到。

对话生成视频复用画布视频播放器的播放、进度、静音和全屏控件，按视频实际比例显示。悬浮或键盘聚焦播放器时，右上角显示资产库图标；未保存时可点击保存，已保存时图标置灰并带有勾选标记。保存状态更新保留当前播放器和播放进度，全屏使用完整画面适配。

未手动命名的生成图片使用简短名称：将提示词中的 `@参考素材文件名` 换成按引用顺序编号的「图1、图2」，去掉开头的生成指令，取第一段有效描述，主体不超过 24 个字符。多图结果追加 `-1`、`-2` 等序号，并使用实际图片格式的扩展名。初次生成和再次生成使用同一规则；明确填写的名称保留。名称整理不调用额外模型，不修改生成提示词、参考图或已有图片的名称，完整内容仍在生成信息中保留。

视频生成、视频文件下载和资产库收藏分别处理：

- 模型生成完成后立即登记历史，再下载视频文件到应用的 uploads 目录。
- 文件下载成功后，历史记录和原任务都使用本地地址，避免依赖有有效期的模型下载链接。
- 下载失败保留生成成功状态及历史记录，显示「重试下载」。普通刷新、返回页面不会反复发起失败的下载。
- 手动重试只下载原视频，不重新提交生成请求。文件还未下载成功时，手动保存会返回明确错误，不会虚报已加入资产库。
- 下载允许公共 HTTPS 地址及管理员配置的模型网关同源地址。重定向仍需逐次验证，其他内网地址不会因网关例外而被放行。

相关接口：

| 接口 | 行为 |
| --- | --- |
| `GET /api/assets` | 生成历史，保留现有引用和画布查询的兼容性 |
| `GET /api/assets?collection=library` | 只返回手动保存的资产 |
| `POST /api/assets/{id}/library` | 幂等地保存至资产库 |
| `DELETE /api/assets/{id}/library` | 幂等地移出资产库，保留生成历史及引用 |
| `POST /api/tasks/{id}/history-asset` | 获取视频历史记录，不收藏 |
| `POST /api/assets/{id}/retry-file` | 重试原视频的文件下载，不收藏、不重新生成 |
| `POST /api/assets/from-task` | 兼容原手动保存接口，保存视频至资产库 |

记录使用 JSON 字段 `in_library`、`library_saved_at`，不需要更改数据库表结构。视频记录另含 `file_status` 和 `file_error`。图片、音频任务及 Agent 消息返回的媒体信息会读取当前收藏状态。

验证覆盖上传、三种媒体生成、手动收藏、下载失败与重试、重复保存、账户隔离、集市页面返回、画布使用和 PostgreSQL 隔离测试。测试使用临时数据库或独立 PostgreSQL schema、模拟模型响应，不调用真实收费模型。

服务器累计更新包按用户要求单独生成，安装与回滚步骤见 [2026-10-19 更新说明](server-update-20261019.md)。日常本地修改不自动生成镜像或补丁包。
