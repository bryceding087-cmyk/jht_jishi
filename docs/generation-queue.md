# 图片与视频生成队列

首页、对话、手动画布、Agent 调用同一组图片／视频提交接口，任务先写入 PostgreSQL，再由进程内调度器执行。仍要求单个 Uvicorn worker，无需 Redis 或独立任务服务。

## 并发与顺序

- 每个执行账号跨全部项目、对话与 Agent，图片不限制并发，视频最多并发 10 个任务；全系统的视频任务合计最多并发 100 个。必须同时满足账号和系统额度，超出时保留在等待队列。管理员替成员操作时，数据仍属于原项目所有者，执行额度与凭据使用已记录的提交账号。
- 同账号同类型按持久化入队序号执行；用户之间轮转调度。凭据失效的待提交任务跳过，避免阻塞其他可执行任务。
- 队列仍保存模型网关地址和实际 API Key 对应的 SHA-256 指纹，不保存当前集市 Key。共享 API Key 不再额外限制为 5 个任务；不同账号、模型、网关和 Key 的视频任务都计入同一个全系统 100 个额度。
- 图片不受账号、供应商凭据池或旧的 64 个工作线程上限约束，也不占视频额度。旧的供应商并发环境变量和持久化记录中的旧 `pool_limit` 不再参与并发判断。
- 正在提交、供应商处理中、结果待核对的视频均占用账号及系统名额，服务重启恢复后继续计入；完成或释放名额后，等待任务按原有轮转规则继续执行。
- 视频取得供应商任务编号后继续占用名额，完成、失败、取消或超时后释放。图片和视频的下载、入库状态独立展示。

Agent 制作按真实依赖分批执行。当前批次中独立的节点可以并行进入队列，所有前置素材就绪后才提交后续批次。最多 5 个节点协调线程等待媒体结果，真正的模型生成由同一队列限制。节点、连线、模型和引用在提交／回填时仍校验，合成沿用已有 FFmpeg 流程。

## 页面与接口

侧栏、画布底部的任务队列按钮及弹窗已移除；后台调度和状态查询继续工作。对话支持图片／视频连续提交，单次 POST 仍防止双击重复提交；音频沿用原有同对话互斥。

图片的 `queue_limit` 和 `queue_global_limit` 为 `null`（不限制），视频分别为 `10` 和 `100`。任务队列信息和状态查询包含 `queue_state`、`queue_ahead`、`queue_limit`、`queue_global_limit`、`can_cancel_queue`；队列接口另返回账号上限 `limits` 和全系统上限 `global_limits`。排队位置仅统计当前账号同类型等待任务，不透露其他用户信息。位置和等待状态会随调度变化，不承诺固定开始时间。

| 接口 | 用途 |
| --- | --- |
| `GET /api/generation-queue` | 当前账号的图片、视频未完成任务及账号／全系统并发限制 |
| `POST /api/generation-queue/{kind}/{id}/cancel` | 取消未提交的排队／等待凭据任务；`kind` 为 `image_task` 或 `task` |
| `POST /api/generation-queue/{kind}/{id}/confirm-stopped` | 用户核实供应商请求已结束或未创建后，释放结果未知任务的名额；不会发起生成 |

已提交的任务不能通过「取消排队」取消，返回 409。尚未接入供应商远端取消协议。用户主动删除作品、切换页面或关闭页面也不会视为供应商任务结束。

## 恢复与计费边界

队列记录存放在现有 `records` 表的 `generation_queue` 类型下，无需新建数据库表。入队发生在提交事务成功之后；提交事务回滚不会启动模型请求。已接收的任务在返回接口前完成持久化入队。

- 从未提交的等待任务：服务重启后重新调度，保留原请求编号。
- 已有供应商视频编号：只恢复 GET 查询，复用原任务，不再 POST。名额保留至任务结束或连续 30 分钟没有有效进展。
- 进程中断时正在执行、未取得可核对结果的请求：标记结果待核对，最多保留名额 30 分钟，不自动重发。
- 读取超时：暂时保留未知结果状态，达到 30 分钟无有效进展时判定失败，不自动重新提交。已完成的部分图片与历史媒体保留。
- 排队期间集市凭据失效：显示等待原账号重新连接；该账号重新进入并查询任务／队列时刷新凭据。不会换用其他账号的 Key。
- 升级前遗留的未完成请求：保守接管；即使无法识别原凭据，视频也会计入对应账号和全系统并发额度。

## 30 分钟超时

等待提交、等待凭据、正在执行、供应商处理中和结果未知均受超时规则约束。入队、开始执行、任务阶段变化、取得供应商任务编号或新增图片结果会更新进展时间；重复查询、更新数据库时间不会续期。服务重启沿用持久化时间。

连续 30 分钟没有有效进展后，任务标记为 failed，保存 queue_timed_out_at，从活动队列移除并释放名额。失败历史保留供查看。停止继续提交和查询，迟到响应不能恢复任务状态或覆盖新结果。已提交的供应商请求可能继续执行；本地失败不会调用远端取消，也不会自动重发收费请求。

## 验证

`tests/test_generation_queue.py` 覆盖图片无并发上限、视频每账号 10 个／全系统 100 个、跨账号和凭据统计、公平性、重启、超时释放与正常进展；`tests/test_generation_queue_api.py` 覆盖新限额返回、共享 Key 的账号额度、认证、隔离、幂等和队列恢复；`tests/test_media_stop_results.py` 验证超时与迟到响应、成功结果的竞态。测试使用隔离数据及模拟供应商，不调用真实收费模型。
