# 管理员系统日志

管理员登录后，左侧导航出现「系统日志」。也可通过 `/?view=logs` 进入；普通用户不显示入口，所有日志接口都会再次检查管理员身份。集市成员不会因为持有集市 Key 而获得管理员权限。

## 用户操作

记录登录、退出、项目／对话修改、素材操作、模型配置修改、生成提交、停止、取消排队等修改请求，以及打开项目／对话和下载素材的操作。记录时间、已验证的操作者身份、账号、角色、集市组织和工号（有提供时）、来源 IP、接口、HTTP 状态、耗时、资源 ID、生成请求编号和操作追踪号。

登录失败中的「尝试登录的账号」是用户输入，不代表已验证的身份。IP 使用服务器识别的客户端地址，不直接信任请求中的转发头。若使用代理，应按原有部署规则配置受信任的代理。

操作追踪号由服务器生成，在对应响应的 `X-JHT-Request-ID` 中返回。生成请求编号、建绘通任务 ID、供应商任务 ID 是不同的标识；可以分别搜索，排查重复点击、提交待确认和供应商任务异常。

仅保存允许的元数据，不存完整请求／响应正文、密码、Cookie、Authorization、集市绑定或媒体凭据、模型 Key、上传文件内容及 URL 查询参数。诊断文字中的常见凭据格式和签名链接会被脱敏。

## 生成任务与队列

支持图片、视频、音频、Agent 和本地合成任务。展示操作者、任务类型、模型、提示词摘要、请求编号、供应商任务 ID、任务状态和队列状态。详情包含生成参数、关联项目／对话、队列执行账号、入队序号、开始执行时间、最近进展、超时释放、错误信息、状态变化时间线和关联操作。

顶部展示全系统视频占用、视频等待提交、结果待确认和近 24 小时更新的失败／暂停任务数量。视频占用按现有调度器的正在提交、供应商处理中和结果未知状态统计，显示全系统 100 个、每账号 10 个的额度。音频、Agent 和合成本身没有图片／视频队列记录时，队列状态显示为空；其媒体子任务分别列出。

支持按用户、日期、任务类型、任务状态、队列状态、请求或任务编号筛选。操作日志支持按执行结果和操作名称筛选。每页 30 条，可手动刷新或每 10 秒自动刷新；离开页面后停止自动刷新。详情最多展示最近 200 条任务状态变化和 20 条关联操作。管理页读取数据库快照，不发起模型请求，也不重发待确认任务。

## 持久化与启用边界

复用现有 `records` 表，新增 `audit_event` 和 `generation_event` 记录类型，无需新增表或依赖。任务和队列状态变化在业务记录的同一数据库事务中保存；重复轮询、心跳及单纯更新时间不生成重复事件。操作记录在请求结束后保存，记录失败会写入服务器错误日志，并保留原业务请求结果。

已有生成任务可直接查询，历史操作不会补造。用户操作及任务状态变化从新版代码启用后开始积累；刷新、重启后仍可查询。日志随数据库备份保存，当前没有自动过期删除或管理页删除功能。

| 接口 | 用途 |
| --- | --- |
| `GET /api/admin/logs/users` | 用户筛选列表，不含认证凭据 |
| `GET /api/admin/logs/summary` | 全系统队列与异常概况 |
| `GET /api/admin/logs/operations` | 用户操作日志，支持分页和筛选 |
| `GET /api/admin/logs/tasks` | 跨用户生成任务与队列快照，支持分页和筛选 |
| `GET /api/admin/logs/tasks/{kind}/{id}` | 任务、队列及状态变化详情 |

列表接口支持 `user_id`、`q`、`since`、`until`、`page`、`page_size`。时间使用 Unix 秒，`page_size` 最大为 100。操作接口另支持 `outcome`；任务接口另支持 `task_type`、`status`、`queue_state`，其中 `queue_state=active` 筛选所有未结束的排队及执行任务。

验证入口：`tests/test_admin_logs.py` 覆盖权限、操作者身份、集市组织信息、脱敏、分页、任务关联及状态变化；`tests/verify_admin_logs.py` 用隔离数据库和真实 Chrome 验证导航、筛选、分页、详情、移动布局及普通成员隔离，不请求真实模型。
