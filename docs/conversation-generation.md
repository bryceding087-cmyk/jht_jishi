# 对话生成并发规则

手动图片、视频和音频生成按对话 ID 限制在途任务。同一对话的上一项任务结束前，发送和再次生成都不可用；首页新建对话、其他对话可以独立提交，包括同一种媒体类型的不同对话。

前端为每个对话维护独立状态。新草稿使用本地独立标识，创建对话后立即绑定返回的对话 ID。返回首页、新建或切换对话时替换草稿对象，避免旧请求的回调覆盖新对话的提交状态。任务响应丢失后，仅重新检查对应对话，重试保留原请求编号。

发送状态查询与媒体任务轮询独立执行、独立续约查询计时器。媒体轮询只针对当前显示对话；切换对话不等待旧轮询完成。即使某个视频状态请求一直未返回，也不能阻塞其他对话的发送状态检查。

`GET /api/conversations/generation-state?conversation_id=<id>` 查询指定对话。省略 ID 返回空闲状态；无权访问、已删除或不存在的对话返回 404。管理员与所有者操作同一对话时共享限制。

后端使用对话级进程锁及 PostgreSQL 事务 advisory lock，并只检查、恢复当前对话的任务。任务记录提交后才启动工作线程；重复请求复用已有任务。应用仍使用单个 worker，供应商调用在后台执行。

回归覆盖同一对话重复提交、不同对话并发、新建对话、管理员与所有者、未知请求结果、页面切换、事务回滚及中断恢复。PostgreSQL 测试使用 `tests/postgres_fixture.py` 创建并清理独立 schema，测试不调用付费生成服务。前端使用内存 DOM 执行生产事件处理函数，不代表实际浏览器视觉验收。
