# 用户隔离与管理员权限

更新日期：2026-10-18。

## 使用规则

- 普通用户只能读取和管理自己的画布、项目文件夹、资产及分组、角色、生成任务、对话和 Agent 创作记录；首页最近内容、回收站和素材引用同样遵守该规则。
- 管理员通过同一个登录页面输入管理员账号和密码，进入同一个创作系统，可以查看、管理全部用户的数据。没有免密管理入口；账号角色由服务端已验证的登录会话确定。
- 模型配置和 API Key 由管理员统一管理。普通用户可以查看模型列表、选择模型生成内容，但不能新增、编辑、删除配置或修改系统默认模型，也不会收到密钥片段。
- 新记录由服务端保存 `owner_id` 和创作者信息。管理员编辑用户的记录时保留原归属及原创作者；复制画布属于执行复制的账号。任务输出继承所属创作上下文，创作者保留实际提交者。
- 各用户的生成请求编号相互隔离。后台任务及恢复运行会从已保存记录恢复身份；成员无法通过轮询接口、缓存结果或媒体 URL 绕过权限。
- 无权访问的记录与文件返回 404。未登录的 API 请求返回 401，页面访问跳转登录。上传目录支持带权限检查的 GET、HEAD 和视频 Range 请求。
- 切换账号或退出登录时，其他已打开的应用页同步刷新；最近 Agent 对话的本地记录按用户分别保存。

## 历史数据迁移

启动时执行 `data_access.migrate_ownership`，通过原有 `owner_id`、创作者或明确的父记录关系推断归属，包括任务输出、对话与 Agent 的事件、文档和操作。无法可靠确认归属的旧记录保留为空，仅管理员可见；不会为了分配归属而伪造创作者信息。

第一次应用 `user-isolation-v1` 前，会保存数据库备份；旧 SQLite 库生成 `.sqlite3`，PostgreSQL 使用一致性事务导出。迁移写入标记，并清理现有登录会话，让所有用户（包括管理员）重新输入账号密码登录。后续正常重启不会重复清理有效会话。账号、密码、素材文件和记录内容不删除。

实际数据库副本的迁移演练结果：1 个画布、98 份资产、24 个对话、8 个 Agent 运行记录及其 1,080 条关联记录可确定归属。10 个画布、134 份资产、4 个文件夹及部分历史生成任务无法确定归属，保留为管理员可见。第二次执行的修改数为 0，验证了重复启动不会重复迁移。

本地服务已于 2026-10-18 重启并完成实际迁移，登录地址为 `http://127.0.0.1:8000/login`。迁移前检查没有正在执行的生成任务，实际归属统计与演练一致。数据库备份为 `data/backups/user-isolation-1792264938022161500.sqlite3`，包含原有 1,593 条记录，SQLite 完整性检查通过。`/api/health` 和 `/login` 返回 200，未登录访问 `/api/projects` 返回 401。启动日志为 `outputs/runtime/server-20261018-032216.err.log`。

同日后续已将全部 1,593 条记录及 2 个账号迁入 PostgreSQL 17.11。迁移前另存 `data/backups/pre-postgresql-1792267085296490800.sqlite3`；逐条核对业务文档、账号字段及密码哈希一致，旧 SQLite 文件哈希保持不变。正式服务使用 SQLAlchemy 和 PostgreSQL；SQLite 仅用于测试及读取历史库。归属、创作者和媒体路径使用真实 SQL 列及索引过滤，详见 `docs/database-deployment.md`。

## 实现位置

- `data_access.py`：访问上下文、角色判断、记录授权、归属推断及迁移。
- `auth_service.py`：把已验证的会话身份绑定到请求；保护页面、接口与静态媒体响应。
- `app.py`：统一记录读写授权、不可变归属、后台任务身份、素材引用校验、模型管理权限与上传文件授权。
- `conversation_service.py`、`agent_runtime.py`：对话、Agent 查询与修改授权，以及管理员的全量视图。
- `public/session.js`、`public/login.js`、`public/agent-chat.js`：账号切换和会话展示。
- `public/model-manager.js`：根据服务端权限展示管理按钮。
